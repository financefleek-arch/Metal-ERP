Where each verb lives

  • Create — the + New button in the rail header. A split-button when a scope has more than one create path (Sales: blank invoice / from a duplicate). Inward's is ↑ Upload PDF — a file picker, not a form.
  • Read — click a rail row → it loads in the detail pane. URL updates (/sales/1218) so it's linkable and back-button-safe. No separate "view" mode.
  • Update — you just type in the detail pane; edits autosave to the draft (PUT). The named buttons (Finalize, Approve, Cancel) are state transitions, not "save".
  • Delete — in the ⋯ menu, and only offered when the record's state allows a hard delete. Otherwise the menu shows Cancel / Reject instead.

Rules baked into the shell

  • A finalized invoice has no Delete — only Cancel (status → cancelled, number retired, stays in the list struck through).
  • An approved inward bill has no Delete — only Reject before approve; after approve it's immutable (masters already created).
  • Delete is a real row removal only for: a draft invoice, an un-approved inward bill, an unused item/party (no documents reference it).
  • Deleting a party/item that's referenced → blocked with a count ("on 12 invoices"); offer Archive instead (hidden from pickers, kept for history).
  • Every destructive action confirms, and writes audit_log.
