Using the exact invoice in the screenshot (18 lines, 2 discounted lines @ 40% totalling 1,102.40). Display-only change — tax.py math is untouched. Updated: "Net Amount" label, per-line entered-% in brackets, footer row kept.

The anomaly: Subtotal 10,306.03 is already net of the two line discounts (it equals the AMOUNT column sum). Then Discount −1,102.40 appears to subtract again — yet Grand Total 10,306.00 barely moves. Two near-identical 10,306 figures sit either side of a 1,102 discount that seems to do nothing. Reads as a bug to any customer.

Now the column adds up: 11,408.43 (gross) − 1,102.40 = 10,306.03 − 0.03 = 10,306.00. Every row is a clean subtraction. The discount clearly comes off something bigger, and it's echoed as a footer total in the DISC. column where it belongs — not orphaned under AMOUNT. Rows are spaced (5px vs 2px), Grand Total gets a double underline.

Per-line %: the Disc. cell shows discount_pct as the operator entered it — 40% (143.60). If the discount was typed as a ₹ figure (discount_pct is null), the cell shows just the amount, no bracket. Nothing is recalculated.

Decisions locked in

  • Middle line is called Net Amount (not "Taxable Value").
  • Keep the in-table footer total row.
  • Discount % in brackets = the % the operator entered (discount_pct), shown verbatim. If the discount was entered as a ₹ amount, no % — just the figure.

What changes display only

  • invoice_v1_nongst.html — Disc. cell (per line): when ln.discount_pct is set, render {{ ln.discount_pct|int }}% ({{ ln.discount|money }}); when null, render just {{ ln.discount|money }} as today. discount_pct is already on invoice_line and already passed to the template via invoice.lines.
  • invoice_v1_nongst.html — line table footer row: one row after the last line — label Total (gross before discount), the discount sum in the Disc. cell, gross (subtotal + discount_total) in the Amount cell. Rendered only when discount_total > 0.
  • invoice_v1_nongst.html — totals box: relabel + reorder to a straight subtraction:
      • Gross Amount = subtotal + discount_total  (shown only if discount > 0; else box starts at Net Amount)
      • Less: Discount = - discount_total
      • Net Amount = subtotal - invoice_discount  (existing taxable_total)
      • Round Off = round_off
      • Grand Total = grand_total
  • Spacing: totals rows padding: 2pt 4pt → 4pt 6pt; rule above Net Amount; double bottom border on Grand Total; fixed min-width on the number column so figures align.
  • No-discount invoices: box collapses to Net Amount / Round Off / Grand Total, no footer row — nothing new on the common case.

What does not change

  • api/app/domain/tax.py — no new fields, no math change. subtotal, discount_total, taxable_total, round_off, grand_total already exist on ComputedInvoice / the Invoice model. "Gross Amount" is derived in the template.
  • pdf.py — no new context needed; discount_pct rides along on each line object.
  • Web preview (previewTotal.ts / InvoiceEditorPage) — out of scope unless you want the on-screen preview to match too (small follow-up).
  • Stored/frozen invoice totals, number sequence, amount-in-words — untouched.

One thing to confirm

  • discount_pct is a "persisted UI hint only" — it's saved when the operator uses the % toggle, left null when they type ₹. Existing invoices created before this habit, or any where ₹ was typed, will simply show the amount with no bracket. That's the intended behaviour, just flagging that older bills won't retroactively show a %.
  • Format: 40% (143.60) — OK? Alternative: 143.60 (40%) (amount first, matching the old cell).
