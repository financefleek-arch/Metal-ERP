Party de-duplication — the create-time gate

Operators free-type party names, so the same firm lands three times (still / steel / SS, Pvt Ltd vs Pvt. Ltd., double spaces). The fix is a resolver ladder (GSTIN → phone → normalized name → trigram fuzzy) that runs before INSERT and forces a choice.

BUILT 2026-09-08 — backend + UI in one uncommitted change. Backend: party.legal_name_normalized + migration 0023 + resolve_party() + structured 409 (party_exists / party_maybe_exists) on POST/PATCH /api/parties with ?force=true (fuzzy-only bypass) + POST /api/parties/resolve. UI: this review. Backend suite 420 pass (+18). Not run in a browser — static mock.

1 · Standalone New-Party form + Quick-create dialog

Both grew a debounced /parties/resolve call on the name / GSTIN / phone fields. The SimilarParties panel (shared component) shows matches inline; picking one hands the existing party straight back to the caller.

3 · Invoice-editor PartyPicker — richer rows, supplier surfacing

Debounced to 250 ms, min 2 chars. No role filter — a firm on file only as a supplier now shows here (badged); picking it widens its role to both. Each row carries city / state + "last billed". The "+ Create" line is de-emphasised to a muted "None of these — add … as new".

4 · Review checklist

  • Panel copy for each method: gstin/phone ("A party with this … already exists"), exact ("This name is already on your list"), fuzzy ("N similar parties…").
  • Debounce feel — does the panel flicker while typing? (300 ms name, 400 ms gstin/phone.)
  • "Use this" on a fuzzy candidate → the picked party flows into the invoice line / parties list exactly as a freshly-created one would.
  • "Create as new" (force path) only appears for party_maybe_exists, never for party_exists.
  • Editing the name after a 409 clears the warning and re-enables Create.
  • Supplier badge + role-widen on pick in the PartyPicker.
  • Mobile: dialog panel doesn't overflow; "Use this" buttons stay tappable.
