Two levels: process list, then data entry

The idea: one level lists what needs doing — sales drafts, inward bills to review, items to confirm — and a second level is the focused editor for a single document. Sales invoicing and inward-bill review stop competing for nav space; they become two entries in the same queue, feeding one shared item_resolution engine. Below: options for each level, side by side.

The inward review screen inherits whichever choice this is — its lines table gets the same column set, with the match cell appended. So picking here settles both editors at once.

Both editors, one engine — why the two-level split works

Level 2 looks like two screens but is one pattern: a party, a line grid, a gated primary button. The lines resolve to catalogue items through the same code — so the process list can treat a sales draft and an inward bill as the same kind of row.
