Units of measure: one fixed set of four

Replaces the free-text UOM story and the per-line piece / kg toggle with a single strict picker — nos, kg, doz, gross — used identically in the invoice editor and the Items forms. Dozen & gross expand into the printed piece count.

What changed at a glance

BeforeAfter
Amber banner with per piece / per kg buttons that set uom + rateMode + newMode Amber banner is text only. A first-class Unit dropdown sits between Qty and Rate on every line.
Unit <select> hidden behind a “change unit” link, only for two-unit items Unit <select> always visible. Options are the fixed 4 (plus the row’s own legacy value if it has one).
rateMode a separate stored choice rateMode derived: kg → "kg", else "piece". Single choke point in patchRow.
A doz line counted as its raw qty (5) compute_measure multiplies: 5 doz → 60 in “Count”; 2 gross → 288.
16-entry UOMS list feeds every picker PRIMARY_UOMS (the 4) for the invoice line + an item’s primary unit; the wide list stays for secondary / purchase unit.

The item-default lifecycle (“last billed wins”)

  • A free-typed line has no item until finalize.
  • At finalize, a line with no match creates the Item with uom = line.uom and rate_mode = kg if weight else piece (finalize.py, item-create branch).
  • For every finalized line linked to an item, if the billed unit differs from item.uom, the item is updated to the billed unit (and its rate_mode re-derived). So an Items-tab edit can be superseded by the next invoice — surfaced by the form note above.
  • Multi-line invoice, same item in two units → the last line (sl_no order) wins.
