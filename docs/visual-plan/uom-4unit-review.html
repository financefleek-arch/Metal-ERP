Units: one canonical table, rate_mode retired

Two changes that go together:

  1. One canonical unit table — shared/units.json — read by the API (app/domain/units.py) and, via a generated file, by the web app. Adding a unit is a one-row edit.
  2. rate_mode is gone. It was a 2-value piece | kg enum that duplicated what uom already says. Every consumer now keys off uom + is_weight_uom().

The canonical table (shared/units.json)

value kind kg_factor piece_mult is_mrp primary aliases nos count — 1 yes yes no pc pcs piece each unit nug kg weight 1 — no yes kgs kilo kilogram doz count — 12 yes yes dz dozen gross count — 144 no yes grs gro g weight 0.001 — no no gm gms gram quintal weight 100 — no no qtl mt weight 1000 — no no ton tonne pair count — 2 yes no pr bundle / coil / sheet / length / ft / m / sqft / sqm / ltr / box / pkt / btl (primary=no)
  • primary=yes → shown in the strict billing picker (invoice line + an item's primary unit): nos / kg / doz / gross.
  • primary=no → the wider list (an item's secondary / purchase unit, and legacy data).
  • A unit not in the table passes through lowercased, not blanked — a real but un-tabled unit stays recognisable.

How the two sides stay in sync

shared/units.json | |--- app/domain/units.py reads JSON at import | '--- web/scripts/gen-units.mjs --> web/src/lib/units.generated.ts (runs in `npm run build` / `npm run dev` prebuild) api/tests/test_units.py asserts the generated .ts matches the JSON row-for-row (edit the JSON, forget to regen -> this test fails)

Dozen / gross in the printed totals

Sl Description HSN Qty Unit Rate Amount 1 Steel Tumbler 7323 5.000 doz 90.00 450.00 … ┌───────────────────────────────────────────────────────────┐ │ Total weight 487.500 kg · Count 60 pcs · 1 weighment │ └───────────────────────────────────────────────────────────┘

Line prints 5 doz verbatim; the aggregate "Count" is piece-expanded (5 doz → 60, 2 gross → 288). PDF template markup unchanged — compute_measure does the multiplication.

The item-default lifecycle ("last billed wins")

  • A free-typed line has no item until finalize.
  • Finalize creates the item with uom = normalize_uom(line.uom).
  • Every later finalize: if the billed unit (folded) differs from item.uom, the item is updated to it. An Items-tab edit can be superseded by the next bill — surfaced by the form note.

Legacy data

Tally import stored base_units verbatim (Doz, PKT, Mtr, Kgs…). The importer now folds via normalize_uom, and a one-time CLI folds what's already in the DB:

python -m tools.normalize_uom --all --out uom-changes.csv # dry run, report only python -m tools.normalize_uom --tenant <id> --apply # write folded values

Pure spelling fold — only rows whose value changes; an un-tabled unit is lowercased, never blanked.
