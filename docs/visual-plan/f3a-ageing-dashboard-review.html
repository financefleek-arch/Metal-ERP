4 · Bucketing rules (the actual logic)

Due date

due = invoice.date + tenant.default_credit_days
Default credit days = 0 → "due on invoice date", which is exactly today's implicit behaviour, so existing tenants see no change until they set a credit period. Per-party override (party.credit_days) is out of scope for F3a.

Which bucket

Each open invoice's live balance_due (not its original total) drops into the bucket its due date falls in, measured against as_on (default today):
age = as_on − due
age ≤ 0 or ≤ 29 ⇒ <30 days · 30–59 ⇒ 30+ · 60–89 ⇒ 60+ · 90+ ⇒ >3 months. Four internal keys lt30, d30, d60, d90p; labels are display-only.

Opening balance

Folded in the same way collections_summary() already does: an opening debit ages by opening_balance_as_of; if that's null it lands in <30 days. An opening credit reduces the party's net, never a bucket.

Query shape

One aggregate, party-driven LEFT JOINs — same discipline as collections_summary() so a party with only an opening balance still appears. Returns per party: lt30, d30, d60, d90p, total, worst_bucket, is_overdue, oldest_bill_date, oldest_bill_number, last_payment_date, open_invoice_count. is_overdue = worst_bucket != "lt30" — powers the Overdue chip without a client-side scan.

GET /api/collections is untouched — the PaymentDialog and the current list still call it. F3a adds GET /api/collections/ageing alongside; the page switches its list query to the new endpoint.

5 · Decisions locked (2026-09-09)

  • Buckets: <30 days / 30+ / 60+ / >3 months — four, mutually exclusive, labels display-only over keys lt30 / d30 / d60 / d90p.
  • Boundary: age ≤ 29 ⇒ <30 days; 30–59 ⇒ 30+; 60–89 ⇒ 60+; ≥ 90 ⇒ >3 months.
  • Credit-days default 0 — reproduces today's numbers exactly until a tenant sets a period. Tenant-wide only for F3a.
  • Net total → caption under the strip (no summary tile).
  • "<30 days" colour → neutral grey (nothing to chase). Null-as_of opening balances also land here.
  • Overdue = worst bucket > 30 days → new scope chip, radio-exclusive with Owes us / Overpaid / Either (Overdue ⊂ Owes us). Per-row "Send statement". Bulk multi-select send is F3c.
