Keeping data sane without slowing down billing

Free-typing “anything, sort it later” gives you a month of SS Balti No 3 / s.s balti-3 / BALTI 3 ss. The fix isn’t mandatory forms — it’s shaping the free field gently, constraining the structured fields hard, and making cleanup continuous.

Six layers, least friction first
1
Normalize the key, not the display. Store name (shown on invoice, as typed) + name_normalized (dedupe key, hidden). Auto-create only if the normalized key is new.
2
Synonym / abbreviation map (tenant-editable). ss = s s = stainless, alu = al = aluminum → aluminium, pcs = piece → nos. Owner adds patterns; re-run over old items to fold retroactively.
3
Type-ahead that pushes toward existing items. Fuzzy (trigram) match on name + aliases. Existing match is the default — Enter picks it; “+ Create new” takes 3 keystrokes. Near-miss nudge: “Did you mean SS Balti No.3 (16×)?”
4
Structured entry for calc/grouping fields. UOM, Category, item_type = pick-lists from day one. HSN = lookup against a shipped reference table (search by code or description, stored as FK) — not free text. Rate / weight / qty = numeric inputs. Only the name is genuinely open.
5
Continuous cleanup, not a quarterly purge. Dashboard “12 look like duplicates” → merge queue, do 5/day. Weekly digest. Merge is non-destructive — old spelling becomes an alias, still resolves.
6
Guardrails against nonsense. Warnings, not blocks (except numerics): rate 0 on finalize → block; rate far off this item’s history → “unusual, confirm?”; same item twice on a bill → “merge lines?”; name <3 chars / all digits → “looks incomplete”.
Normalization pipeline (deterministic)
lowercase
→ trim + collapse whitespace
→ punctuation . - / ( ) , " ' → space
→ collapse whitespace again
→ apply synonym map
→ keep token order (no sorting)
All of these resolve to one item
"S.S. Balti No.3" → ss balti no 3
"s s balti-3"  → ss balti 3 → ss balti no 3
"Stainless Balti (3)" → ss balti no 3
"BALTI No 3 SS" → balti no 3 ss  ← token order differs
The last one is caught by the Layer-3 fuzzy nudge, or a one-click merge later. Token-sorting would fix it but breaks angle 40x40 vs 40x40 angle — not worth it.

Schema
item.name · item.name_normalized   INDEX gin_trgm(name_normalized)  -- pg_trgm fuzzy
item_alias(item_id, alias_text, alias_normalized)   UNIQUE(tenant_id, alias_normalized)
synonym(tenant_id, from_token, to_token)  -- seeded ~30 metal-trade entries
item.uom / item.category  -- enum, not free text
hsn_code(code PK, description, chapter, default_gst_rate, valid_from)  -- shipped ref list; item.hsn_code FK
Phase 1 cost
Pipeline + column: ~½ day, before first bill
Synonym seed list: a few hours
Fuzzy type-ahead: pg_trgm index, one line
Merge tool + dashboard widget: 2–3 days, just after go-live
Principle: constrain the structured fields hard, shape the free field gently, make correction continuous. Some mess still gets in — but it’s mess normalization folds together automatically, not mess a human decodes six months later.
