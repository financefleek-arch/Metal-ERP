4Pull masters

The one control that does the work. It makes a job; the agent picks it up on its next check-in (~1 min), exports from Tally, uploads, and the backend stages the rows. The section polls the job while it runs.

Chip, over the pull's life

Queued Running Waiting on Tally Ready to review Failed
  • Queued — job made, agent hasn't checked in.
  • Running — agent has it; exporting / uploading / parsing.
  • Waiting on Tally — agent says Tally is closed or no company open. Not an error; retries each check-in.
  • Ready to review — rows staged; shows a "Review 214 parties + 1,880 items →" link.
  • Failed — bad XML / upload / storage. Shows the message + Retry.

Button disabled while a pull is live

A pull queued / running, or ready but not yet reviewed, blocks a second (409). Caption: "a pull is already waiting for review — commit or discard it first."

6End-to-end, once the operator clicks Pull

Operator · Ops console Clicks Pull masters now. A job is created; the button disables, chip → Queued.
Companion agent · shop PC Next check-in (~1 min) it takes the job and asks Tally for an All Masters export over the local gateway.
Tally Prime · shop PC Returns the masters XML. (Closed / no company open → agent reports it, chip → Waiting on Tally, retries.)
Companion agent Uploads the XML to cloud storage; tells the backend the job is done.
Backend Downloads, parses, stages parties + stock items into a review batch. Chip → Ready to review.
Operator Opens the existing import review screen, checks the matches, clicks Commit. Parties + items now exist for the firm.

The review screen is not new

Commit runs through the same import review UI the manual "upload a Tally XML" flow already uses — same match rules, same per-row create / link / skip, same commit. The pull fills that screen instead of a file upload. F1a adds no review UI.

What gets created

  • Parties — Sundry Debtors → customers, Sundry Creditors → suppliers. Blank fields filled; nothing overwritten.
  • Stock items + their product groups.
  • Opening balances — only for a party with no invoices/payments yet, flagged in the review screen.
  • Sales / tax / cash ledger names → remembered for the ledger map; no records created for them.
