Party Opening Balance

Design review. Palette + primitives mirror web/src/index.css. Not a live page — don't open in a browser as a build.

BUILT 2026-09-07 — uncommitted, not deployed. Full backend suite green (374 passed / 1 skip, +10 tests), frontend tsc/eslint/build clean. Migration 0021 applies on next alembic upgrade head. These panels are the design intent; the shipped code matches them. Touch points: (1) Details form field, (2) Account-tab statement, (3) invoice editor's "Bill to" block — editable inline for a new client, (4) the invoice picker's Quick-Create-Party dialog, (5) the invoice PDF's "previous outstanding" block. Rule: editable only while the party has zero ledger history (no finalized invoices, no payments); locks after the first transaction.

Guardrail: any unit label shown to a user is pcs, never nos (canonical value stays nos, display goes through uomDisplay()). This feature is all ₹ and shows no unit labels — noted so it isn't dropped if quantity text is added later.

Unlocked → the ₹ field PATCH /parties/{id}es the party on blur (debounced, same pattern as PartyForm); a failed save shows inline and never blocks the invoice. Locked → reuse GET /parties/{id}/ledger (already cached via ["party-ledger", id]), read entries[0].running_balance. The picker's PartyListItem carries opening_balance + opening_balance_locked so no extra fetch is needed to decide which mode to show.

5 · Invoice PDF — the "previous outstanding" block

Added after the first review. On a finalized invoice's PDF, below Grand Total, whenever the party owes anything else (opening balance and/or other unpaid invoices). Omitted entirely when that's ₹0.

invoice_v1_nongst.html · totals box (tail)
Net Amount8,918.75
Round Off0.25
Grand Total8,919.00
Previous outstanding (before this bill)10,000.00
Add: This invoice8,919.00
Total amount due18,919.00

previous_outstanding_for_party(party_id, exclude_invoice_id=this) = opening balance + Σ balance_due of the party's other finalized invoices − on-account credit. Uses each other invoice's live balance, so a later payment on an earlier bill lowers this figure on a re-render. Net-credit party → shows negative.

What changes

  • Migration 0021 — party.opening_balance NUMERIC(14,2) NOT NULL DEFAULT 0, party.opening_balance_as_of DATE NULL.
  • payments.py — has_ledger_history() helper; party_ledger() seeds the running balance and prepends a synthetic kind="opening" entry; outstanding_balance_for_party() and the collections aggregate add the opening term; previous_outstanding_for_party(..., exclude_invoice_id=) for the PDF.
  • parties.py — _out() returns opening_balance, opening_balance_as_of, opening_balance_locked; update_party() returns 409 if a locked opening balance is changed.
  • Schemas — fields on PartyBase / PartyOut / PartyUpdate; "opening" added to PartyLedgerEntry.kind.
  • Web — PartyForm + NewPartyForm fields (disabled when locked); PartyAccountTab renders the opening row; InvoiceEditorPage "Bill to" block: editable ₹ field when the picked party is unlocked (PATCH on blur), read-only balance line when locked; QuickCreatePartyDialog gets the ₹ + as-of fields; PartyListItem carries opening_balance + opening_balance_locked.
  • PDF — services/invoices/pdf.py + invoice_v1_nongst.html: previous-outstanding / total-amount-due block below Grand Total.
