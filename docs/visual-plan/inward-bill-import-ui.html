Inward Bill Import — planned UI

A feature-flagged module (tenant.ext_inward_import). Upload a supplier's PDF invoice → the module extracts it, matches or stages the supplier and every line against the tenant's masters, reconciles the totals, and on Approve produces a downloadable Tally Purchase-voucher XML the accountant hand-imports. Six mid-fi screens below; sample data is the Sugal Foods invoice INV2526-5667.

Approve gate

POST /api/inward-bills/:id/approve Phase X5

Approve stays disabled until three things hold, and the button spells out what's missing. On click it runs one transaction: create staged supplier + items, link every line, build the XML, flip to Approved.

Blocking checks

✓ Totals reconciletaxable + CGST + SGST + round-off = grand total, ±0.05
✓ Supplier resolvedmatched to Sugal Foods by GSTIN
! Every line resolvedlines 3 & 7 are AI-matched and not yet confirmed
· HSN checkline 4 HSN 21069092 present in reference list — ok

On Approve — one transaction

1Create the staged new supplier party + address (none here — GSTIN matched; on a matched party, bump last_txn_at)
2Create staged new items source = auto_from_purchase, status = unconfirmed
3Link every line's matched_item_id; bump last_purchase_rate
4Build the Tally Purchase-voucher XML → write to the volume
5status → Approved · write audit_log
confirm the AI matches on lines 3 & 7 to enable
