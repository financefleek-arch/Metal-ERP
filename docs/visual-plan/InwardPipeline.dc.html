Line → item: the resolution ladder (stop at first hit)
1
normalized-exact — normalize(description) == an item.name_normalized (tenant-scoped). conf 1.00
2
alias — matches an item_alias.alias_normalized (this is how a supplier's wording learns over time). conf 0.98
3
pg_trgm fuzzy over names + aliases, HSN as a boost / tie-break: +0.15 same HSN, −0.10 different. Take the top only if adjusted ≥ 0.72 and it beats #2 by ≥ 0.10.
4
LLM disambiguation — ambiguous / weak. One batched call per bill: line + this tenant's top-5 candidates (name, HSN, last rate) → an id or NONE. Never invents an item. conf capped 0.80, badged "AI-matched".
5
new UNCONFIRMED item — source=AUTO_FROM_PURCHASE, HSN validated against the shipped reference list (unknown HSN → review flag). Created on Approve.
HSN is a strong signal, never a key — many products share one HSN (the whole Sugal Foods invoice is 21069092). New purchase items flow into the same catalogue-accretion story: they show up UNCONFIRMED on the Items page and get merged/confirmed with the existing tooling.
Supplier → party (GSTIN is the key)
GSTIN exact match on party.gstin (role supplier/both) → link; a matched customer is promoted to both.
No GSTIN on the PDF → normalized-name trigram, proposed never auto-linked.
No match → stage a new party: name from header, GSTIN, PAN from GSTIN chars 3–12, state from the prefix, one address. Created only on Approve.
supplier_template — learns per GSTIN
Saved on first Approve of a new supplier (opt-in "save as template?"). Stores column x-ranges, header anchors, the UOM map, and the default purchase / tax ledger names for that GSTIN. The tenant's next bill from the same supplier skips steps 3–5 and the LLM.
