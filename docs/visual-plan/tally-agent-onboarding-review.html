Visual Plan · F1a / F10 · pre-build review

Tally Agent — seamless shop onboarding & health reporting

Provisioning a firm’s agent is the installer. The system mints the key, injects it into appsettings.json, packs the zip, and hands over a ready download link. Nobody — not the Fleek operator, not the shop — ever edits a config file. And once the shop runs it, the agent’s heartbeat tells Fleek whether it reached TallyPrime or not.

Fleek operator (platform-admin console) Metal ERP backend (does the assembly) Shop staff (owner / accountant) Tally Agent (Windows service at the shop)

4Failure branches

Console showsMeansWho fixes itRecovery
Agent → Fleek: Offline (> 5 min no checkin) Install not run, PC off, no internet, or key rotated since download. Fleek → shop: PC on / online? Re-run installer. If key was rotated, they need the new download. Auto on next checkin.
Online; Tally Not reachable: connection refused TallyPrime not running, or server mode off. Shop: open Tally, enable server mode (PDF). No Fleek action. Auto within 60s.
Online; Tally Not reachable: no company open Server mode on but sitting on company-select. Shop: load the company. Auto.
Tally connected; a Pull stuck on “Waiting on Tally” Company closed mid-pull, or a different company loaded than registered. Operator: check the registered company name; lazy auto-cancel frees it after ~10 min. Retry, or self-cancel + re-pull.

5What changes to build this

Backend — the assembly

• On POST /api/admin/firms/{id}/tally-shop (and rotate-key): after minting the key, call build_installer_zip(key, backend_url) (already written, currently unwired) in-process, store the bytes against the firm (R2 object or a blob column), discard the plaintext key.   • GET /api/admin/firms/{id}/tally-shop/installer — platform-admin, streams the cached zip.   • GET /api/tally/installer — the firm’s own WriteUser session, streams the same cached zip for that tenant (so the shop can self-serve from their dashboard).   • _generate_appsettings() gains the TallyMasters block.   • checkin accepts tally_reachable + tally_reason → last_tally_ok_at / last_tally_status on backup_shop (2 nullable cols).   • settings.public_base_url baked into the zip — new env var, push fleek-infra first.

Agent (.NET)

• Each round probe the gateway; stash reachability on AgentContext; pass into CheckinAsync.   • BackendClient.CheckinAsync body gains tally_reachable + reason.   • AgentOptions.TallyMasters already exists — installer just needs to write the section.

install.ps1 (rewrite)

• ShopApiKey / BackendBaseUrl / WatchFolder become optional; if the bundled appsettings.json already has a real key, skip the overwrite entirely. Zero-argument run must work.   • Self-elevate (Start-Process -Verb RunAs).   • Print the first-checkin result before exit.   • Fix the stale tools.make_backup_shop header; strip all non-ASCII (PS 5.1 BOM/em-dash gotcha).

Ops console + shop dashboard

• Ops: replace the “provision” controls with one Set up Tally sync button; after, show Download + Copy link + Rotate key & rebuild, and the two health cells.   • Shop dashboard: a Connect your Tally card — Download button, the one-toggle reminder, and a green state once tally_reachable.   • Disable “Pull masters” with an inline reason while tally_reachable=false.

Prod prerequisite (infra)

A dotnet publish -c Release -r win-x64 --self-contained output at settings.tally_agent_build_dir (/data/tally-agent-build) on the metalerp-api container — volume mount + CI/manual drop. Confirm the mount in fleek-infra compose.

6Open decisions

Where the cached zip lives. R2 object (consistent with backup storage, survives container restarts) vs. a bytea column on backup_shop (simplest, ~40 MB row).
Recommend R2 — the build dir and backup bucket are already there; a 40 MB DB row per firm is avoidable.
Does the shop-facing download need auth beyond the login? The firm’s own WriteUser session is enough to stream their zip. The zip embeds a live key, so the route must be tenant-scoped and never guessable.
Recommend: tenant-scoped route, no extra token; rotating the key is the “revoke a leaked zip” lever.
Backup-folder path in the bundled config. Bake a default (C:\Tally\Backup or the standard TallyPrime data dir), overridable from the console later, or prompt the shop once?
Recommend: default + silent — a wrong path only degrades backup, not masters sync, and is fixable from the console.
“Offline” threshold + alerting. How long with no checkin before red — push/email to Fleek, or dashboard-only?
Recommend: red at 5 min, dashboard-only for the pilot.
Auto-update. Out of scope (re-run a newer install.ps1). Confirm acceptable for the pilot.
Recommend: manual for the pilot; F10 auto-update is a later slice.

Still unavoidably manual

Enabling “TallyPrime acts as Server” is a Tally-side toggle we cannot script. It ships as one screenshot in Setup guide.pdf, and the console’s “Tally: not reachable” state exists to catch the shop that skipped it — visibly, on the Fleek side, within a minute.
