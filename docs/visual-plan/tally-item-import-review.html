Bulk import items from Tally

Upload a Tally Prime Stock Items export (or All-Masters XML). The system parses every <STOCKITEM>, maps the clean fields (name / unit / HSN / GST / type), parses the name for metal · shape · grade · size, matches each against the catalogue by Tally GUID → normalized name → new, and shows a review screen. A GUID we've imported before is recognised and only its blank fields are filled — your manual edits are never overwritten. Nothing is written until you press Import.

Match & write rules

Per stock item, in order:
  • GUID — item.tally_guid == <GUID> (already linked from a prior import) → update blank fields only (uom / hsn / gst / default_rate). If nothing is blank → skip (re-import is a no-op).
  • Normalized name — normalize(<NAME>) == an item.name_normalized (not archived, not merged) → link: set tally_guid, fill blanks. A single strong trigram near-match (≥ 0.82, not exact) → flag (link / create), never auto-links.
  • No match → create: source = import, status = unconfirmed, name + name_normalized, uom, item_type, hsn (seeding hsn_code if unseen), gst_rate, default_rate, and the parsed metal / shape / grade / size_text.
Auto-flagged (held back from Import): a name-only near-match; a name > 200 chars or with disallowed characters; an HSN not in the reference list (offer: seed it with the Tally GST rate, or import without); a stock group that maps to no category (proceeds — category just left blank, not a hard flag); a duplicate GUID within the file.

Never overwritten: a field you already set on an existing item. The importer only fills blanks. Your metal/shape/grade edits, a hand-set price_min/max, a corrected HSN — all survive a re-import untouched.
